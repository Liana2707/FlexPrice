# FlexPrice

## Правила разработки и процессы

1. Ветки и работа с Git

    Основные ветки:

        main — стабильный код, готовый к продакшену, прямые коммиты запрещены.

        develop — основная ветка разработки, интегрируются новые фичи и исправления.

    Для каждой новой функции, исправления или эксперимента используется отдельная ветка с префиксом:

        feature/номер-задачи-имя-задачи (например, feature/1-development-setup), bugfix/номер-багфикса, hotfix/номер-исправления

    Все изменения в develop и main должны проходить через Pull Request.

    После успешного тестирования и проверки PR изменения вливаются соответствующим образом (в develop для новых функций и багфиксов, в main через релизные и хотфикс ветки).

2. Кодирование и стандарты

    Используйте согласованные стандарты кодирования (например, PEP8 для Python).

    Все коммиты должны иметь осмысленные и информативные сообщения.

    Обязательно соблюдение единого стиля кода, отступы, именование переменных и функций.

5. Безопасность и конфиденциальность

    Никогда не храните в репозитории чувствительные данные (ключи, пароли, токены, данные, веса).

    Используйте переменные окружения и .env для параметров конфигурации.

6. Документация

    Вся техническая документация хранится в папке /docs.

    README должен дополняться по мере роста проекта.
